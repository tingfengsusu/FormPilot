## 一、真实页面实测结论（2026-09-19）

| 字段 | 控件类型 | 说明 |
|---|---|---|
| 学校名称 | **文本输入**（`div.school-select`，antd combobox 样式） | 直接录入校名；实测点击/触摸都不会弹出列表，**没有选项集合** → 规范名靠人工确认（`dictionary.kinds.school: text`） |
| 学生类别 | antd 下拉（自定义组件） | 4 个选项：请选择 / 大中专学校学生 / 中学生 / 小学生；大学生选「大中专学校学生」再选 1/2/3 |
| 年级 | antd 下拉（自定义组件） | 12 个选项，**不随学生类别变化**（三个类别下都是这 12 个） |
| 班级 | antd 下拉（自定义组件） | 30 个选项：1班…30班，**不随学生类别变化** |
| 保险期限·起 | 日期选择器（Vant 滚轮） | **只能选今天及之后**；台账里的 8 月分期填不进去 |

其他实测要点：

- 页面打开即弹「温馨提示 / 投保须知」底部弹窗（按钮是倒计时的「我知道了(3s)」），
  **而且每次点击表单后会再次弹出**，全屏遮罩会拦掉所有点击 → 探针已内置把关
  （见 `page/overlay.py`），否则报错会长得像「控件类型未识别」，极其误导
- 页面上有多个同名 class 的下拉（邮箱、证件类型…），**选项查找必须限定在本字段
  自己的面板内**，否则会把别的下拉的候选项当成本字段的（实测把「大中专学校学生」
  喂进了邮箱框，收上来一堆 `xxx@163.com`）

## 三、起期口径（使用者确认 + 2026-09-20 真机修正）

**实测修正**：投保页「保险期间·起」的日期列**从「明天」开始**（今天选不了），
所以下限用 `tomorrow`（不是 `today`）；「止」**由页面按「起 + 364 天」自动算**，
且点不开（不给手动选）→ 只回读校验（`fill_mode: verify_only`）。

- `config/batch.yaml` → `import.period_start_floor: tomorrow`
  （取值：`tomorrow` / `today` / `YYYY-MM-DD` / `off`）
- 起期早于下限 → **整体平移到下限**（止期同步顺延，保持原时长），
  并在导入报告提示 + 每条写 validation（`rule=period_adjusted`，含原值）
- 不修改源台账，原始值以 Excel 为准
- 实测影响：119 条里 **111 条**被平移；录入时（runner）按**录入当天**再取平一次
- 止期不填：页面自动算，回读校验必须等于「起 + 364 天」

### 真机试跑记录（2026-09-20）✅

用真实台账的一条（柳泉小学 / 5年级 / 1班）跑通全链路：
导入 → 确认 → 录入 → 截图 → 「待复核」，回读**零差异**。截图在
`data/screenshots/1/1_马仕豪.png`（**未点「立即投保」**，停在 ¥100.00）。

试跑中修掉的真机问题（都是自动化才暴露的）：

1. **弹窗遮挡**：投保须知弹窗每点一次表单就重弹一次，Filler 的点击路径
   没走遮挡把关 → 第一次试跑卡在第一个字段（方案卡片）。现在 Filler 的
   每次点击都过 `page/overlay.py` 把关
2. **起期下限是「明天」**：原来按「今天」取平 → 日期列里没有「今天」→ 不可选。
   配置改为 `period_start_floor: tomorrow`
3. **止期是页面自动算的**（起 + 364 天）且点不开 → 新增 `fill_mode: verify_only`
   （停用 date 模式填它，只回读校验）
4. **被保人手机号必填**（页面红星）→ 补 `被保人手机号 ← phone` 映射
   （台账里该列=家长手机号）
5. 报错信息被覆盖：填充失败的原因会被「回读不一致」覆盖掉 → 现在两者都保留
6. 学校名称 locator 改为内层 `div.school-select input`（外层是 div，
   Playwright 不能对它 `fill`）

## 六、本轮（2026-09-19）修掉的真实 bug

1. **弹窗「点了又弹」**遮挡全部点击 → `page/overlay.py`：点击前把关 + 被拦截重试
2. **选项面板串字段**：全页找 `[role=option]` 会拿到别的下拉的候选项

   → 限定在本组件内，且只在没找到目标项时才输入
4. **回读校验读到别的元素**（去掉 `>> nth=` 后读到「证件类型」）→ 用完整 locator
5. **nth 索引定位在重渲染后错位** → 同 class 多元素时改用唯一 path
6. 文本字段字典：已映射的**规范名**被二次校验时不认识 → 现在能通过
7. 早期：`batch/dictionaries.py` 与 `page/dropdown.py` 的全角映射表长度不等（模块 import 就崩）；
   `id_card` 地区码无效说明是死代码；`db.clear_batch_sensitive` 在密文上用 SQL LIKE 判断脱敏
